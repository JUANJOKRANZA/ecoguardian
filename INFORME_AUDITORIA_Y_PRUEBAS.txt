CAMBIOS IMPLEMENTADOS
1. Restauración de sesión persistente: la sesión ahora debe coincidir con el rol actual de la cuenta. Si la cuenta fue eliminada, desautorizada o su rol no coincide con el rol de la sesión, se revoca el token y se limpian los parámetros de sesión de la URL.
2. Motor de examen: se añade validación de límites antes de acceder a una pregunta, para evitar un error de índice ante un estado inválido o manipulado.
3. Se añadió una suite inicial de pruebas automatizadas en tests/test_core.py y requirements-dev.txt para instalar pytest en desarrollo.

BLOQUEOS PARA DECLARARLO TERMINADO
1. El ZIP recibido no contiene el prompt maestro citado. Sin él no es posible comprobar fidelidad funcional a los requisitos originales.
2. Las funciones de campeonatos, adjuntos, aislamiento multi-colegio y recuperación de cuentas no están presentes.
3. No se pudo instalar Streamlit desde el entorno ni ejecutar una prueba de navegador.
4. El proyecto utiliza SQLite local. No se incluye configuración de producción con base de datos compartida, copias de seguridad y secretos gestionados.
5. El token de sesión se transporta en un parámetro de URL (`eg_session`); aunque se almacena su hash en la base de datos, la estrategia debe revisarse antes de publicar en internet para reducir exposición en historial, registros o enlaces compartidos.
